# 포털 보안 이벤트 목록 (탐지 담당 김태빈 님께, 2026-10-20 기준)

포털(`app/`)이 남기는 보안 이벤트를 코드에서 직접 뽑아 정리했습니다(86종). 탐지 규칙 R1~R4를 만들 때 쓰는 이벤트는 2절에 따로 모았습니다.
이 문서는 `docs/01_기획.md` 6절(초안)과 `docs/실측_검증계획_A.md` 4절을 대신합니다.

## 1. 어디로, 어떤 모양으로 가나

| 경로 | 내용 |
|---|---|
| 파일 | `logs/security.jsonl` — 한 줄에 JSON 하나. 모든 필드가 그대로 남는다(4MB 넘으면 돌려 쓴다) |
| GELF | `.env` 의 `NEXUS_GELF_ENABLED=1` 이면 UDP 로 `NEXUS_GELF_HOST:NEXUS_GELF_PORT`(이 PC: `192.168.3.10:12201`)에 보낸다(`nexus_team_integration.py`). **허용한 필드만** `_필드명` 으로 보낸다(아래 표). `short_message` 는 `NEXUS <event_type>`, `host` 는 `nexus-portal-<PC이름>`, `_portal_scope=nexus_team` |

**공통 필드(모든 이벤트):** `ts`(UTC ISO), `event_type`, `user`(로그인 아이디, 없으면 `-`), `role`, `src_ip`, `method`, `path`, `decision`(`ALLOW`·`DENY`·`BLOCK`·`WARN`·`INFO`·`ERROR`), `reason`, `request_id`

**GELF 로 함께 가는 부가 필드:** `severity kind field count required resource action outcome tool mode conversation_id via token_fp api_path ms chars resource_id` + (10-20 추가) `target old new markers has_token ext size bytes mime cloud context_chars attachment_chars errno`
— 이 밖의 필드는 파일에만 남습니다. 필요한 필드가 있으면 알려 주세요(비밀값이 아니면 더합니다).

**원칙:** 비밀번호·토큰 원문·대화 원문·문서 본문은 어떤 이벤트에도 남기지 않습니다. 토큰은 지문(`token_fp`, sha256 앞 10자)만, 대화는 글자 수(`chars`)만 남습니다.

**출발지 IP 주의:** `src_ip` 는 지금 실제 접속자 IP 입니다. pfSense 경유로 바꾸면서 pfSense 가 출발지 NAT 를 하면 전부 pfSense 주소(172.16.50.2)가 됩니다 → R1·출발지별 티켓이 무너지므로 이시헌 님과 방식을 정하는 중입니다(`docs/03_팀_연동안내.md` 1절).

## 2. 탐지 규칙에 쓰는 이벤트

| 규칙 | 이벤트 | 판정·사유 | 쓸 필드 |
|---|---|---|---|
| R1 계정 침해 | `login_failure` | DENY, `bad_password`·`unknown_user` 등 | `user`, `src_ip` |
| | `account_locked` | BLOCK, `max_failures` (5회 실패 → 15분 잠금) | `user`, `src_ip` |
| | `login_locked` | 잠긴 계정으로 로그인 시도 | `user`, `src_ip` |
| | `login_success` | ALLOW | 실패 뒤 성공 판단용 |
| | `rate_limited` | BLOCK, `login_ip_limit`(IP 분당 20번) | `src_ip` |
| | `messenger_login_success`, 메신저 로그인 실패도 `login_failure` 로 남음 | | |
| R2 인젝션 패턴 | `suspicious_input` | WARN (차단 안 함). 입력에 인젝션·XSS·경로 탐색 모양이 있을 때 | `field`, `kind`, `path` |
| | `post_created`, `chat_message`, `chat_attachment` | INFO. 게시글·AI 대화·AI 첨부(형식 `ext`, 크기 `size`, 글자 수 `chars`) | 원문은 없음 |
| R3 AI 권한 거부 | `ai_sensitive_output` | WARN, AI 응답에 기밀 식별 문구(`NXC-…`)나 내부 토큰이 섞임. 권한 없는 사용자면 가려서 보여 줌 | `markers`, `has_token` |
| | `ai_restricted_block` | DENY, n8n 이 AI 제한한 사용자가 AI 를 쓰려 함 | `user` |
| | `ai_request` | INFO, AI 호출(제공자 `reason`, `cloud`, `context_chars`, `attachment_chars`) | |
| | `authz_deny` | DENY, 권한 부족 접근(기밀 문서 등) | `resource`, `required` |
| | `confidential_access` | ALLOW, 기밀 문서 열람(`list`·`read`·`ai_context`) | `resource_id` |
| R4 내부 API | `internal_api` | ALLOW(`ok`)/DENY(`bad_token`). `via=direct` 면 HTTP 로 직접 호출, `via=gateway` 면 AI 게이트웨이(병합 후) | `via`, `token_fp`, `api_path`, `src_ip` |
| | `rate_limited` | BLOCK, `internal_api_limit`(IP 분당 30번) | `src_ip` |

**참고:** AI 에이전트·게이트웨이(이시헌 님 `ai-agent` 브랜치)를 합치면 `ai_tool_call`·`ai_tool_deny`·`ai_injection_detected`·`ai_leak` 이벤트가 더해집니다(R2·R3 의 주 근거). 합친 뒤 이 문서를 갱신합니다.

## 3. 전체 목록 (코드 기준 86종)

| 분류 | 이벤트 (판정) |
