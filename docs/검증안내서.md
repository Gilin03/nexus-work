# 검증 안내서 — 어디로 가서 무엇을 하면 무엇이 보여야 통과인가

준비: README의 설치·실행 1~5단계를 마친 상태(`python run.py`가 떠 있고 시드가 들어 있음). 주소는 `http://127.0.0.1:5070`, 계정 비밀번호는 `.env`의 `SEED_*_PW`입니다.
각 항목은 3단계 이내, 30초 안에 끝납니다.

## 1. 로그인 방어와 관리자 잠금 해제

| 단계 | 어디서 | 무엇을 | 통과(보여야 하는 것) |
|---|---|---|---|
| 1 | `/login` | `kim`과 틀린 비밀번호로 5번 로그인 | 매번 같은 실패 문구("로그인할 수 없습니다 …"), 없는 아이디로 해도 똑같음 |
| 2 | `/login` | 이번엔 `kim`의 **올바른** 비밀번호로 로그인 | 여전히 실패(잠김) |
| 3 | `admin`으로 로그인 → 사이드바 **사용자 관리** → kim 행 **잠금 해제** | 다시 kim 로그인 | kim 로그인 성공 |

## 2. 권한 구분(직원은 기밀·타인 자료를 볼 수 없다)

| 단계 | 어디서 | 무엇을 | 통과 |
|---|---|---|---|
| 1 | `kim`으로 로그인 | 사이드바 확인 | **기밀 문서함·재무 보고·관리** 메뉴가 없다 |
| 2 | 주소창에 `/confidential` 입력 | — | "접근 권한이 없습니다"(403), 문서 내용 없음 |
| 3 | **급여** 메뉴 | 목록 확인 | 본인 급여 2건만 보인다. `lee`(팀장)로 로그인하면 영업팀 6건, `admin`은 전체 12건 |

## 3. 경비 상신 → 순차 결재 → 반려 사유

| 단계 | 어디서 | 무엇을 | 통과 |
|---|---|---|---|
| 1 | `kim` → **경비** → 경비 등록 → 상세에서 **결재선**에 `lee`(1차)·`admin`(2차) 선택 후 상신 | — | 결재 문서가 생기고 **결재란**에 상신·1차(결재 대기)·2차(순서 대기) 칸이 보인다. 직원(han 등)이나 본인은 선택지에 없다 |
| 2 | `admin`으로 같은 결재 문서를 열어 승인 시도 | — | 승인 버튼이 없다(1차 차례 전) |
| 3 | `lee`로 로그인 → **전자결재**에서 "결재 필요" 문서 → 반려 사유 없이 **반려**, 이어서 사유를 쓰고 **반려** | — | 사유 없이는 오류, 사유를 쓰면 결재란에 빨간 **반려** 도장, 2차는 "건너뜀", kim 의 경비 상태는 "반려" |

## 4. 입력 공격과 로그

| 단계 | 어디서 | 무엇을 | 통과 |
|---|---|---|---|
| 1 | **주소록(사내 직원 탭)**에 `' OR 1=1-- ` 입력 | 검색 | "검색 결과가 없습니다"(전체 목록이 나오지 않음), 오류 화면 없음 |
| 2 | **자유게시판 글쓰기** 제목에 `<script>alert(1)</script>` | 등록 후 글 열기 | 글자 그대로 보이고 경고창이 뜨지 않는다 |
| 3 | `logs/security.jsonl` 마지막 줄들 | 열어 보기 | `suspicious_input`(kind: sqli, xss)이 JSON 한 줄씩 기록되어 있다 |

## 5. 한 번에 자동으로 (30초~3분)

```bash
python -m pytest -q                              # 기대: 453 passed
python scripts/defense_check.py --report 결과.md  # 기대: 통과 18 · 실패 0, 점검 데이터는 자동 삭제
```

로그인 요청이 많아 서버의 속도 제한(분당 20회)에 걸리지 않도록 스크립트가 알아서 간격을 두므로 몇 분 걸릴 수 있습니다. 끝나면 1분 정도 로그인이 막힐 수 있습니다(1분 뒤 자동 해제, 서버를 다시 시작하면 즉시 해제).

## 막혔을 때

| 증상 | 확인 |
|---|---|
| `docker compose up`이 포트 오류 | PC의 다른 MySQL이 3306을 쓰는 경우 — `.env`의 `DB_PORT`(기본 3307) 변경 |
| 앱이 시작되지 않고 `SECRET_KEY` 오류 | `.env`의 `SECRET_KEY`가 32자 이상의 임의 값인지 확인 |
| 로그인이 계속 실패 | 5회 실패로 잠긴 상태일 수 있음 — 관리자 화면에서 해제 |
| DB 시험이 모두 skip | MySQL 컨테이너가 떠 있는지(`docker ps`) 확인 |
